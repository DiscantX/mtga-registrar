# 3rd Party Mouse Controller Reserach

## Overview of Documentation Insights

Architectural guidelines in [`docs/architecture.md`](docs/architecture.md:15) and Architecture Decision Record 2 in [`docs/decisions.md`](docs/decisions.md:13) establish human-like input automation as a foundational requirement for `MTGA Registrar`. 

Key documentation principles governing mouse automation include:
* **Anti-Detection Strategy ([`docs/decisions.md`](docs/decisions.md:13)):** Automated cursor trajectories and click delays must emulate natural human interactions to reduce flagging risks when operating against MTGA streamed via Nvidia GeForce Now.
* **Modular Separation of Concerns ([`docs/architecture.md`](docs/architecture.md:15)):** Input automation resides in [`src/automation/`](src/automation/), serving higher-level orchestrators such as [`ApplicationController`](src/core/app.py:13) and [`BrowserController`](src/automation/browser.py:11) without exposing low-level PyAutoGUI details.
* **Operational Rules ([`AGENTS.md`](AGENTS.md:18)):** Cursor movements must strictly use non-linear Bezier curves and randomized intervals during batch card additions and deck exports.

## Type Definitions and Locations

Type signatures and parameter definitions related to mouse movement and delays are located across the following files:

* **Cubic Bezier Trajectory Function:** [`generate_bezier_curve()`](src/automation/mouse.py:21)
  * `start: Tuple[float, float]` — Starting cursor coordinates.
  * `end: Tuple[float, float]` — Ending cursor coordinates.
  * `num_points: int = 50` — Number of interpolation points along the trajectory.
  * `control_offset_range: Tuple[float, float] = (-60.0, 60.0)` — Min and max offset ranges for cubic control points.
  * Returns: `list[Tuple[float, float]]`.
* **Mouse Controller Class:** [`MouseController`](src/automation/mouse.py:69)
  * Static methods: [`MouseController.move_to()`](src/automation/mouse.py:73), [`MouseController.click()`](src/automation/mouse.py:116), [`MouseController.drag()`](src/automation/mouse.py:144), [`MouseController.scroll_down()`](src/automation/mouse.py:179).

  * `mean: float` — Average delay in seconds.
  * `stddev: float` — Standard deviation for Gaussian distribution.
  * `min_delay: float` / `max_delay: float` — Hard min/max boundaries.
* **Domain Exception:** [`AutomationError`](src/core/exceptions.py:15)
  * Raised by [`MouseController`](src/automation/mouse.py:69) methods when PyAutoGUI operations fail or lose context.

## Relevant Implementations & Functions

The current custom mouse automation implementation is contained within [`src/automation/mouse.py`](src/automation/mouse.py:1) and supported by timing utilities in [`src/automation/timing.py`](src/automation/timing.py:1):

1. **[`generate_bezier_curve()`](src/automation/mouse.py:21)**
   * Calculates cubic Bezier curves $B(t) = (1-t)^3 P_0 + 3(1-t)^2 t P_1 + 3(1-t) t^2 P_2 + t^3 P_3$ between starting and target cursor positions.
   * Introduces offset control points $P_1$ and $P_2$ scaled by random offsets between -60.0 and +60.0 pixels to create curved, non-linear trajectories.
2. **[`MouseController.move_to()`](src/automation/mouse.py:73)**
   * Gets current position via `pyautogui.position()`, calculates travel distance, and computes dynamic trajectory durations ranging from ~0.15s to 0.6s.
   * Iterates through points generated by [`generate_bezier_curve()`](src/automation/mouse.py:21) and issues `pyautogui.moveTo()` with randomized micro-sleep intervals ([`src/automation/mouse.py:106`](src/automation/mouse.py:106)).
3. **[`MouseController.click()`](src/automation/mouse.py:116)**
   * Optionally invokes [`MouseController.move_to()`](src/automation/mouse.py:73), executes Gaussian delays via [`sleep_random()`](src/automation/timing.py:32), triggers `pyautogui.click()`, and applies post-click settling pauses.
4. **[`MouseController.drag()`](src/automation/mouse.py:144) & [`MouseController.scroll_down()`](src/automation/mouse.py:179)**
   * Encapsulate mouse drag operations (`mouseDown` / `mouseUp`) and mouse wheel scroll notch events (`pyautogui.scroll`) with randomized delays.
5. **Caller Integration Points:**
   * **Deck Scanning & Grid Navigation:** [`ApplicationController.scan_and_click_page()`](src/core/app.py:207) and [`ApplicationController.navigate_to_next_page()`](src/core/app.py:261) call [`MouseController.click()`](src/automation/mouse.py:116) and [`MouseController.scroll_down()`](src/automation/mouse.py:179).
   * **In-Game Browser Navigation:** [`BrowserController.open_help_link_or_browser()`](src/automation/browser.py:48) calls [`MouseController.click()`](src/automation/mouse.py:116) to navigate GeForce Now Edge links.

## Critical Dependencies

As defined in [`pyproject.toml`](pyproject.toml:21):

* **`pyautogui` (`>=0.9.54`):** Lower-level cross-platform library responsible for querying cursor positions (`pyautogui.position`), triggering OS clicks (`pyautogui.click`), mouse presses (`pyautogui.mouseDown`/`mouseUp`), and scrolling (`pyautogui.scroll`).
* **`random` / `math` / `time`:** Standard Python libraries supplying Gaussian normal distribution calculations (`random.gauss`), distance math (`math.hypot`), and micro-sleeping (`time.sleep`).

## Pros and Cons Analysis: Custom [`src/automation/mouse.py`](src/automation/mouse.py:1) vs. External Library (`human_mouse` / `pyclick` / `humancursor`)

### Pros of External Library (e.g. `human_mouse`)

1. **Advanced Physics & Human Motion Models:**
   * External libraries often incorporate Fitts's Law, velocity profiles (acceleration and deceleration curves), mouse overshoot/correction noise, and tremor modeling.
   * Our current custom implementation in [`generate_bezier_curve()`](src/automation/mouse.py:21) uses fixed cubic Bezier points with uniform spatial step distribution, which produces smooth curves but constant point density.
2. **Reduced In-House Mathematical Maintenance:**
   * Offloads curve trajectory math, velocity modulation, and OS-specific cursor movement edge cases to a maintained package.
3. **Simpler Top-Level Trajectory Calls:**
   * Reduces internal code lines in [`src/automation/mouse.py`](src/automation/mouse.py:1) for Bezier curve calculations.

### Cons of External Library (e.g. `human_mouse`)

1. **Third-Party Dependency Risks & Maintenance Status:**
   * Niche human-mouse simulation libraries on PyPI (such as `human-mouse`, `pyclick`, `humancursor`) are frequently single-maintainer projects that can become abandoned, break with newer Python versions (3.10+ / 3.12+), or lag in OS platform updates.
2. **Loss of Custom Error Handling & Domain Exception Integration:**
   * [`MouseController`](src/automation/mouse.py:69) currently wraps lower-level exceptions into [`AutomationError`](src/core/exceptions.py:15). External libraries raise arbitrary generic or internal library exceptions that must be caught and re-mapped to avoid breaking [`EmergencyStop`](src/automation/emergency_stop.py:21) or loop recovery in [`ApplicationController`](src/core/app.py:207).
3. **Lack of Specialized MTGA Interaction Methods:**
   * External mouse packages typically focus only on cursor movement and basic clicking. They do not natively provide customized helper operations required by our workflow, such as:
     * Mouse wheel pagination via [`MouseController.scroll_down()`](src/automation/mouse.py:179).
     * Card drag operations via [`MouseController.drag()`](src/automation/mouse.py:144).
     * Gaussian timing distribution pauses via [`sleep_random()`](src/automation/timing.py:32).
4. **Testability & Mocking Complexity:**
   * Unit tests in [`tests/test_automation.py`](tests/test_automation.py:58) and integration tests in [`tests/test_integration.py`](tests/test_integration.py:46) rely on clean PyAutoGUI monkeypatching. Introducing an external library requires mocking complex internal physics generators or C extensions.
5. **Loss of Fine-Grained Timing Control:**
   * In high-throughput card addition loops (up to 250 cards per deck), precise control over duration thresholds (e.g. `0.15s` to `0.6s` in [`src/automation/mouse.py:98`](src/automation/mouse.py:98)) is necessary to balance speed against detection. External libraries often enforce fixed slow movements.

---

## Conclusion & Architectural Recommendation

Replacing [`src/automation/mouse.py`](src/automation/mouse.py:1) entirely with an external library like `human_mouse` is **not recommended** as a complete substitute because external libraries lack specialized MTGA actions ([`MouseController.scroll_down()`](src/automation/mouse.py:179)), domain exception wrapping ([`AutomationError`](src/core/exceptions.py:15)), and tight integration with [`sleep_random()`](src/automation/timing.py:32).

**Recommended Hybrid Approach (if improved human motion fidelity is needed):**
Keep [`MouseController`](src/automation/mouse.py:69) as the project's public API wrapper. If curve generation or movement realism needs enhancement, replace internal calls in [`generate_bezier_curve()`](src/automation/mouse.py:21) or [`MouseController.move_to()`](src/automation/mouse.py:73) with the external library while retaining the surrounding class interface, timing distribution, error handling, and test mocks.
